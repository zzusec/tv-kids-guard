# 开发与发布

需要 JDK 17、Android SDK 35、build-tools 35.0.0 和 Python 3。用 `ANDROID_HOME` 或本机 `local.properties` 的 `sdk.dir` 指定 SDK。

## 测试与开发版

```bash
./gradlew testDebugUnitTest assembleDebug
python3 -I -B -m unittest discover -s tools -p 'test_*.py' -v
```

开发 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。开发签名不能覆盖正式版，CI 不包含生产私钥。

## Android 4.4 兼容

最低版本为 API 19，现代 Android 路径保留。Robolectric 固定为 4.12.2：这是仍支持 API 19 的版本，4.13 起移除了该运行时。

- 亮屏计时在 API 19 使用 `PowerManager.isScreenOn()`；关屏、待机和锁定时暂停，用量持久化和家长密码规则不变。
- 界面提供旧版主题、图形资源和控件样式，不依赖原生 Material、VectorDrawable 或 API 21 的文字与按钮接口。
- API 19 更新使用 AlarmManager 和独立服务；API 21 以上保留 JobScheduler。旧系统启用 TLS 1.2，仍验证主机、证书、APK 签名及版本。
- API 19 通过系统安装器、在有效家长维护授权下确认安装；不继承进程重启前的授权，不清除原有密码或时长数据。
- Android 4.4 没有 Lock Task，也没有本应用使用的 Device Owner 防强停策略。普通管理员仍启用时，`PackageManagerService.deletePackageX` 的 `isPackageDeviceAdmin()` 会拒绝直接卸载；系统可先停用管理员，因此仍须保持设置入口拦截。页面按实际状态区分两类保护。发现旧版设备所有者时拒绝不安全解除，不恢复出厂。

回归覆盖 API 19 的计时/关屏/重启、鉴权、界面资源、权限入口和更新路径，并保留 API 24、33 的相关测试。原生图形截图测试在 API 33 运行，不把预览当作真机截图。小米电视 2 的实机验证仍待 ADB 恢复，未验证厂商后台保活和遥控行为。

## 遥控器输入模式

2.5.7（versionCode 38）按数字键能力选择默认输入模式并提供本机手动切换；2.5.11（versionCode 42）把检测改成跨设备取并集，并让实测到的数字按键优先于能力报告。两种模式均不依赖系统输入法（IME）、WebView 或触摸输入。家长验证、首次设置和修改密码、到时锁屏、每日时长、临时加时均须可在有实体数字键或仅有方向键、OK 的遥控器上完成。

- 自动检测：未手动选择时，把每个非虚拟且带 `SOURCE_KEYBOARD` 或 `SOURCE_DPAD` 的 `InputDevice` 报告的数字键合成并集，普通数字键和小键盘数字键任一支持即算该数字存在；并集覆盖 0–9 就默认隐藏屏幕数字盘，只显示实体输入区。单台设备报不全不再算作「没有数字键」，并集缺一字或检测结果未知时显示数字盘，不按品牌或型号硬编码。`hasKeys()` 抛异常或返回长度不等于 20 的畸形结果按「该设备不提供数字」处理，一台设备的畸形答复不能否决其它设备的证据。设备按并集补齐后立即停止查询，不再询问后面的设备。
- 实测优先：`onPhysicalDigit(KeyEvent)` 收到真正来自非虚拟设备的数字按键时写入 `tvguard_remote` 的 `physical_digits_seen`，并收起屏幕数字盘——这是给厂商 keymap 报错留的后门。`deviceId` 未知（-1）、设备是虚拟设备或事件来自屏幕数字盘自身都不算证据，不能因为一次合成按键就把家长的数字盘收掉。
- 手动选择：系统 keymap 不等于遥控器实际按键，不能把能力报告当作实物按键保证。所有输入页均提供方向键和 OK 可达的「使用屏幕数字盘」或「使用遥控器数字键」切换按钮；选择只保存在本机 `tvguard_remote`。数字键能力未知时选「使用屏幕数字盘」只是默认，第一次实测到数字键就会收起；数字键已知（检测或实测）时再选「使用屏幕数字盘」会写入 `pad_pinned`，读取顺序为 `pad_pinned` > `physical_digits_seen` > `show_keypad` > 自动检测，家长的选择最终优先。切换与学习只改变输入方式，不更改 PIN、计时或家长授权。
- Gate 与 `PinDialog` 导航：实体模式默认聚焦输入区，方向下或右到「使用屏幕数字盘」，OK 展开；虚拟模式从数字盘顶部按方向上到「使用遥控器数字键」，OK 收起。
- 屏幕输入：方向键选择数字，OK 输入；「删除」「确认」均有可聚焦的屏幕按钮。数字盘导航不能把方向左误当成删除。
- 实体数字键输入：保留直接输入，输入后左键删除、OK 直接确认。返回取消当前输入，不能因此授予家长权限、解除锁定或更改额度。
- 家长 PIN 保持 6 位遮罩、原有错误提示与失败冷却。修改密码仍需再次验证；数字盘按钮与实体数字键共用校验、授权和提交路径，不因输入方式放宽边界。每日时长和临时加时显示数字，沿用原有限额与今天生效规则。
- Lock 默认聚焦「家长管理」按钮，OK 进入家长验证，成功后只打开面板。从该按钮出发，虚拟模式方向下或右进入数字盘、方向左到切换按钮；实体模式方向下或右到切换按钮，OK 展开数字盘，实体数字键也可直接输入。在锁屏直接输入正确家长密码同样只打开管理面板：2.5.12 起没有「今天不限时」，锁屏仍在面板之下、离开面板即恢复；切换模式本身不会解除锁定。
- 保留暗色面板、显著的 DPAD 焦点和原有卡片对齐；验证门页与锁屏保留独立主题。隐藏时 Gate/Lock 居中、最大 560dp，`PinDialog` 恢复最大 560dp 单栏；显示数字盘时分别沿用原最大 900dp 与宽屏最大 760dp 布局。隐藏数字盘不留空位，切换后重排输入区域，并将焦点保留在可见控件上，不改主面板列宽、间距或卡片布局。

发布前应检查完整数字键、跨设备拼出完整数字键、缺一字与检测未知时的默认模式，实测数字按键收起数字盘、虚拟与合成按键不学习、家长手动选择被固定保留及本机持久化，所有输入页的切换可达性与隐藏后布局、焦点；同时检查两种输入路径、屏幕删除/确认、返回取消、PIN 遮罩、失败冷却、授权失效和锁屏两种入口。构建与自动化结果由最终发布验证汇总，不把原生渲染预览当作真机证据。小米电视 2 的 ADB 仍待恢复，不能宣称已通过该电视的实机数字盘验收。

## 计时与右上角

2.5.10（versionCode 41）处理 Sony BRAVIA 4K 2015 上确认的两件事：待机被算成观看时长，以及「今天不限时」时右上角完全空白。2.5.12（versionCode 43）把「今天不限时」这个状态本身删掉，角标因此只剩倒计时一种形态，待计时规则不变。

- 计时基线是 `SystemClock.uptimeMillis()`，不是 `elapsedRealtime()`。后者在深度休眠期间照旧前进，而前台服务的 1 秒 tick 在待机时会被系统停掉，醒来后一次补跑就把整段挂钟差当作观看时长扣进当天额度——Sony BRAVIA 4K 2015 上家长确认电视可以连续数十小时处于待机，并要求待机一律不计入。`countedDelta()` 同时封顶单个周期的补量（`MAX_COUNTED_TICK_MILLIS`，4 秒），主线程被卡住、看门狗补跑或服务重启都只会补一个周期。亮屏、灭屏、服务创建和解除锁定四个入口都重新对齐基线，因此熄屏的分钟不会在唤醒那一刻被追溯扣除。
- 额度判定仍是「亮屏且未锁定」，所以关屏、锁屏与待机都不计时；跨到更晚的日历日才由 `Prefs.rollOverIfNeeded()` 清零，时钟回拨不给免费的额度重置。
- 右上角角标由 `GuardService` 持有：未锁定时 `updateCountdown()` 显示「剩余 MM:SS」，最后 5 分钟转红。2.5.10 曾在这天被家长密码解锁时把同一枚角标换成琥珀色「今天不限时」（`showUnlimitedNotice()`）并与面板的 `today_override` 提示对齐；2.5.12 把这一状态、这段提示和那一行标记一起删除——家长密码不再买时间，角标就只剩下倒计时一种形态，也不会再出现空白角标被孩子读成「防护已关」的情形。锁定态不显示角标，只有全屏黑幕与锁屏 Activity。
- 悬浮窗权限缺失时不贴角标（API 23 起 `Settings.canDrawOverlays`），面板另有「倒计时未开启：需允许悬浮窗权限」警告；API 19/20 由清单权限决定，不存在运行时撤销。
- `CountdownOverlayTest` 在 API 19/24/33 断言：模拟一小时深度休眠后 tick 不增加当天时长；tick 被饿 20 分钟后最多补 4 秒；熄屏十分钟不扣、唤醒后只从亮屏那刻开始计；未锁定时窗口里恰有一枚文本角标、文字以「剩余 」开头且额度接近 30 分钟减去已看时间，反复 tick 不叠加；面板给出 10 分钟临时加时后同一枚角标的剩余正好多出 600 秒；无悬浮窗权限时不贴任何窗口；额度耗尽时进入锁定且没有倒计时角标。`PrefsAuthTest` 另断言旧版写下的 `unlocked_today` 在升级后的第一次构造 `Prefs` 时被删除，且删除后时长锁重新生效。

## 设置入口保护与恢复

2.5.9（versionCode 40）以普通应用恢复原有密码拦截为目标，不要求系统预装、root 或 Device Owner：每次进入设置页都要求家长密码，同时消除「输入密码后再次要求输入密码」的验证死循环。`MainActivity.requireParent()` 保护图标入口，`GuardService` / `LockActivity` 保持额度锁定，`AppLockService` 保护已识别的设置及卸载页面；三条路径分别验收，不能把图标有密码等同于系统设置受保护。

- 无障碍声明 `canRetrieveWindowContent=true`，仅调用 `getRootInActiveWindow()` 获取所属包名并回收节点，不遍历控件、不读取或保存文字。查询可能返回空，窗口事件仍保留为识别来源；查询异常记录日志并在面板提示，定时回查继续重试。
- 连接时清除旧前台和设置解析缓存，250 ms 回查重新查询当前窗口，不依赖重连后必定补发窗口事件。未知包变化时立即重新解析，查询失败约 1 秒重试，同一未知包正常约 30 秒重新识别；局部失败不丢弃已识别的受保护包。
- `isEnabled()` 检查无障碍总开关及启用组件，兼容完整和缩写组件名；`isConnected()` 来自服务连接、解绑和销毁回调。配置已启用不代表服务正在运行。普通应用不能自动重新开启系统已关闭的无障碍权限。
- 每次进入设置页都要求家长密码：`AdminSession` 有效不作为设置页通行证，验证页与时长锁屏照常拉起。Sony BRAVIA 4K 2015 上的死循环不是靠记住密码修的，而是靠下一条规则修的：管理面板是半透明窗口，它下面的设置页仍然可见并持续上报自己是前台窗口，拦截服务因此在面板之上反复拉起验证页；面板 `onPause` 会撤销会话，下一个验证页就真的再次要求输入密码，输入后循环重现。日志证据是 `MainActivity` 启动后约 0.15～0.4 秒紧跟一条 `AdminAuthActivity` 启动，循环到家长放弃为止。
- 拦截服务在自家家长界面在屏时一律不动手，这是现行唯一的防死循环机制：验证页可见、已授权面板可见或 `GuardService` 的家长界面租约有效都不再拉起验证页或锁屏，不依赖具体机型的前台窗口判定。家长会话本身不放开设置，每次进入仍要家长密码。
- 只有显式维护授权短时放行系统页；管理员激活返回（含取消）、更新返回或维护到期后恢复拦截；未经验证按返回不露出原设置页。
- `AppLockServiceTest` 覆盖当前窗口恢复、重连、解析重试、连接状态与维护边界，并断言「有效会话之上的设置页仍要密码」「维护结束后同一个设置页重新要求密码」；`SettingsGateLoopTest` 用真实的验证页→面板交接和「面板之下的设置页仍上报前台」复现死循环，断言面板在屏时不弹验证页也不弹锁屏、家长离开后同一个设置页重新要密码、时长用尽的锁屏在家长离开面板后回来；`MainActivityRemoteTest`、`MainActivitySettingsTest` 验证图标鉴权和真实警告。自动化不替代电视上的桌面长按、应用详情和卸载入口验收，不能据此认定本次电视故障根因。

## 防卸载附加保护

普通设备管理员仍启用时，系统的直接卸载检查会拒绝移除；这不等于所有设置流程都无法卸载，也不等于要求本应用密码。设置入口拦截才是日常保护主线。

- 家长在面板按 `55`，经系统 `ACTION_ADD_DEVICE_ADMIN` 确认页激活；应用不静默激活。仅在限时维护授权下打开该页，返回后结束维护并按 `isAdminActive` 读回真实结果。
- 系统 `DeviceAdminAdd` 的部分流程可通过 `uninstallPackageWithActiveAdmins()` 停用并卸载。`onDisabled` 发生在停用后，只能撤销旧授权并尝试拉起密码门，不能否决已经完成的操作。
- 关闭防护仍走 `DeviceProtection.remove()` 的家长确认和读回核验，不恢复出厂。普通模式不承诺阻止系统强停、清除数据或未识别的厂商入口。
- `UninstallProtectionTest` 与 `DeviceProtectionTest` 覆盖 API 19/24/33 的激活维护、返回恢复、停用后重新验证、策略读回与系统确认页无法解析的情况；不是实际卸载验收。

## 正式发布

私钥保存在仓库外；默认读取 `~/.config/tv-kids-guard/signing.properties`，也可用 `TVGUARD_SIGNING_PROPERTIES` 指定：

```properties
storeFile=/绝对路径/release.keystore
storePassword=<密钥库密码>
keyAlias=<原签名别名>
keyPassword=<私钥密码>
```

递增版本号，使用原签名构建。输出目录需为空或不存在：

```bash
./gradlew testDebugUnitTest assembleRelease
python3 -I -B tools/release_update.py --apk app/build/outputs/apk/release/app-release.apk --out app/build/outputs/ota --notes '更新说明'
python3 -I -B tools/release_update.py --apk app/build/outputs/apk/release/app-release.apk --out app/build/outputs/ota --notes '更新说明' --publish
```

发布前检查 `tv-kids-guard.apk`、`update.json` 和 `SHA256SUMS`。发布工具只上传这三个文件，并校验 `config/release-certificate.sha256` 中的公开证书指纹；不要提交私钥或签名密码。
