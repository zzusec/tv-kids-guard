# 开发与发布

需要 JDK 17、Android SDK 35、build-tools 35.0.0 和 Python 3。用 `ANDROID_HOME` 或本机 `local.properties` 的 `sdk.dir` 指定 SDK。

## 测试与开发版

```bash
./gradlew testDebugUnitTest assembleDebug
python3 -I -B -m unittest discover -s tools -p 'test_*.py' -v
```

开发 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。开发签名不能覆盖正式版，CI 不包含生产私钥。

## Android 4.4 兼容

最低版本为 API 19，现代 Android 路径保留。Robolectric 固定为 4.12.2：这是仍支持 API 19 的版本，4.13 起移除了该运行时。

- 亮屏计时在 API 19 使用 `PowerManager.isScreenOn()`；关屏、待机和锁定时暂停，用量持久化和家长密码规则不变。面板状态这一路判据（`Display.getState()`）自 API 20 才存在，因此 API 19 仍只有电源管理一个判据，2.5.16 的双判据从 API 20 起生效，读不到时一律按「亮着」处理，不会因为接口缺失而冻结当天额度。
- 界面提供旧版主题、图形资源和控件样式，不依赖原生 Material、VectorDrawable 或 API 21 的文字与按钮接口。
- API 19 更新使用 AlarmManager 和独立服务；API 21 以上保留 JobScheduler。旧系统启用 TLS 1.2，仍验证主机、证书、APK 签名及版本。
- API 19 通过系统安装器、在有效家长维护授权下确认安装；不继承进程重启前的授权，不清除原有密码或时长数据。
- Android 4.4 没有 Lock Task，也没有本应用使用的 Device Owner 防强停策略。普通管理员仍启用时，`PackageManagerService.deletePackageX` 的 `isPackageDeviceAdmin()` 会拒绝直接卸载；系统可先停用管理员，因此仍须保持设置入口拦截。页面按实际状态区分两类保护。发现旧版设备所有者时拒绝不安全解除，不恢复出厂。

回归覆盖 API 19 的计时/关屏/重启、鉴权、界面资源、权限入口和更新路径，并保留 API 24、33 的相关测试。原生图形截图测试在 API 33 运行，不把预览当作真机截图。小米电视 2 的实机验证仍待 ADB 恢复，未验证厂商后台保活和遥控行为。

## 遥控器输入模式

2.5.7（versionCode 38）按数字键能力选择输入模式并提供本机手动切换；2.5.11（versionCode 42）把检测改成跨设备取并集，并让实测到的数字按键优先于能力报告；2.5.13（versionCode 44）删掉手动切换，输入模式只剩硬件判定这一条来源；2.5.14（versionCode 45）把判定不出来时的整屏数字盘换成一枚数字键盘图标，数字盘要按 OK 展开。两种输入方式均不依赖系统输入法（IME）、WebView 或触摸输入。家长验证、首次设置和修改密码、到时锁屏、每日时长、临时加时均须可在有实体数字键或仅有方向键、OK 的遥控器上完成。

- 硬件检测：把每个非虚拟且带 `SOURCE_KEYBOARD` 或 `SOURCE_DPAD` 的 `InputDevice` 报告的数字键合成并集，普通数字键和小键盘数字键任一支持即算该数字存在；并集覆盖 0–9 就只用实体输入区，数字盘和图标都不出现。单台设备报不全不算作「没有数字键」，并集缺一字或检测结果未知时给一枚数字键盘图标，不按品牌或型号硬编码。`hasKeys()` 抛异常或返回长度不等于 20 的畸形结果按「该设备不提供数字」处理，一台设备的畸形答复不能否决其它设备的证据，整个查询抛异常时按未知处理、把数字盘留在图标后面，不能让验证页崩溃。设备按并集补齐后立即停止查询，不再询问后面的设备。
- 实测优先：`onPhysicalDigit(KeyEvent)` 收到真正来自非虚拟设备的数字按键时写入 `tvguard_remote` 的 `physical_digits_seen`，并收起屏幕数字盘与图标——这是给厂商 keymap 报错留的后门。`deviceId` 未知（-1）、设备是虚拟设备或事件来自屏幕数字盘自身都不算证据，不能因为一次合成按键就把家长的数字盘收掉。
- 读取顺序只剩两级：`physical_digits_seen` > 硬件检测。2.5.13 起 `RemoteInputMode` 的构造会删除旧版留下的 `show_keypad`、`pad_pinned`，因此升级后即使本机以前固定过数字盘，也重新由硬件决定；`RemoteInputMode` 不再暴露 toggle，`LockActivity`、`AdminAuthActivity`、`PinDialog` 不再有 `handleKeyEvent` 的切换分支，锁屏提示与 `PinDialog` 帮助文字相应改为只描述当前可用的输入方式。学习与判定变化只改变输入方式，不更改 PIN、计时或家长授权。
- 数字盘的状态只有两个来源：`digitsKnown`（能力并集或实测证据，跨屏持久）与 `padRequested`（家长在本屏按过图标，不持久）。`usesOnScreen()` 为「未判定且已按过图标」，`showsRequest()` 为「未判定、没按过、且数字盘当前可用」。图标是 `RemoteKeypad.padRequestButton(Context)` 造的原生 `Button`（tag `keypad_request`，图形为自绘 `KeypadGlyph` 3×3 点阵），由 `RemoteInputMode.requestButton()` 交给三个入口界面挂进自己的文案列（`entry_copy` / `copy`），`RemoteInputMode` 不持有布局。`handleKeyEvent(event)` 在界面把按键交给数字盘之前先跑：图标有焦点时吃掉导航与 OK（DOWN 装填、UP 才 `performClick`，取消或长按重复都不触发），输入区有焦点时方向下或右把焦点交给图标；数字盘被禁用（冷却、服务恢复中）时 `showsRequest()` 为假，图标随之隐藏，`syncRequestVisibility()` 由 `LockActivity.refreshUi()` 与 `AdminAuthActivity.render()` 在 `setEnabled` 之后调用，并把已经落在图标上的焦点退回输入区。按图标只是展开数字盘，不授予任何家长权限；换一屏重新从图标开始。
- Gate 与 `PinDialog` 导航：检测到数字键时默认聚焦输入区，直接按遥控器数字键；未判定时同样聚焦输入区，按方向下或右选中图标、OK 展开数字盘并聚焦第一个数字，从盘顶部按方向上回到输入区（`setUpperFocusTarget`），锁屏把该目标设为「家长管理」按钮。
- 屏幕输入：展开数字盘后方向键选择数字，OK 输入；「删除」「确认」均有可聚焦的屏幕按钮。数字盘导航不能把方向左误当成删除。
- 实体数字键输入：保留直接输入，输入后左键删除、OK 直接确认。返回取消当前输入，不能因此授予家长权限、解除锁定或更改额度。
- 家长 PIN 保持 6 位遮罩、原有错误提示与失败冷却。修改密码仍需再次验证；数字盘按钮与实体数字键共用校验、授权和提交路径，不因输入方式放宽边界。每日时长和临时加时显示数字，沿用原有限额与今天生效规则。
- Lock 默认聚焦「家长管理」按钮，OK 进入家长验证，成功后只打开面板。从该按钮出发，未判定数字键时方向下或右选中图标、按 OK 才展开数字盘；已检测到时屏幕上没有数字盘也没有图标，直接按遥控器数字键即可。在锁屏直接输入正确家长密码同样只打开管理面板：2.5.12 起没有「今天不限时」，锁屏仍在面板之下、离开面板即恢复；选中图标或展开数字盘本身不会解除锁定。
- 保留暗色面板、显著的 DPAD 焦点和原有卡片对齐；验证门页与锁屏保留独立主题。隐藏时 Gate/Lock 居中、最大 560dp，`PinDialog` 恢复最大 560dp 单栏，未判定时这一栏在输入区下方多出一个居中图标；显示数字盘时分别沿用原最大 900dp 与宽屏最大 760dp 布局。隐藏数字盘不留空位，判定变化后重排输入区域，并将焦点保留在可见控件上，不改主面板列宽、间距或卡片布局。

发布前应检查完整数字键、跨设备拼出完整数字键、缺一字与检测未知时的输入模式，实测数字按键收起数字盘与图标、虚拟与合成按键不学习、旧版 `show_keypad`/`pad_pinned` 被清除且不再强制显示数字盘，以及隐藏后的布局与焦点；未判定的电视上还须检查图标是屏幕上唯一的数字输入提示、方向下或右可选中它、OK 才展开数字盘、冷却期间图标与数字盘一起隐藏、换屏后重新回到图标；同时检查两种输入路径、屏幕删除/确认、返回取消、PIN 遮罩、失败冷却、授权失效和锁屏两种入口。2.5.13 删掉切换按钮后没有人工兜底：厂商 keymap 报了 0–9 而遥控器实际没有数字键时，家长只剩实体输入这一条路，这类电视一旦遇到必须在检测上补证据而不是恢复按钮；2.5.14 的图标只补回「按一步拿到数字盘」，不改变这条判定。2.5.16 起还须在实机上确认待机这条路：额度用尽后放着不管，15 秒左右屏幕应当自己熄灭（以前被锁屏按着不放），按遥控器任意键后先看到锁屏；未锁定时按遥控器关机十分钟再开机，右上角「剩余」只该少掉真正看的那几分钟，不能少十分钟；锁屏在面板熄灭期间不得把电视点亮。2.5.15 起还要在实机上检查退后台这条路：面板按返回键和 <code>00</code> 都落到电视机桌面且不再被锁屏抢走，桌面之上没有黑幕；从桌面打开任意应用立刻回到锁屏；孩子在锁屏按 HOME 仍被锁回；待机后再亮屏先看到锁屏；<code>33 立即锁定</code> 与验证页返回照旧锁屏；关掉无障碍后退出面板同样回到锁屏而不是桌面，且这几步都不改变今天已看时长。构建与自动化结果由最终发布验证汇总，不把原生渲染预览当作真机证据。小米电视 2 的 ADB 仍待恢复，不能宣称已通过该电视的实机数字盘验收。

## 计时与右上角

2.5.10（versionCode 41）处理 Sony BRAVIA 4K 2015 上确认的两件事：待机被算成观看时长，以及「今天不限时」时右上角完全空白。2.5.12（versionCode 43）把「今天不限时」这个状态本身删掉，角标因此只剩倒计时一种形态，待计时规则不变。2.5.16（versionCode 47）把「屏幕亮着」这一条判据换成两个部件同时作证，并删掉锁屏的强制保持亮屏。

Sony 实机采样（只读 `dumpsys`，每 5–7 秒一次）给出的结论：

- 遥控器 关机 确实会走到框架：`Notifier.sendGoToSleepBroadcast` → `com.sony.dtv.intent.action.PRE_SCREEN_OFF` → `ACTION_SCREEN_OFF`，`mWakefulness` 由 `Awake` 变 `Asleep`，`Display Power: state=OFF`、`mGlobalDisplayState=OFF`、`screenState` 2→0、`interactiveState` 1→0，且切换发生在一次采样之内（无中间态）。这一段本来就不计入当天额度。
- 同一段 77 分钟待机里 `uptimeMillis` 前进了 69 分钟——Sony 在待机中持有 `PARTIAL_WAKE_LOCK 'heat_control'` 与 `'WebApiWakeLock'`，SoC 不 suspend，所以 2.5.10 的「靠开机时长识别待机」在这台机器上几乎不起作用，只有面板状态可靠。
- 采样期间锁屏窗口是整机唯一的 `SCREEN_BRIGHT_WAKE_LOCK` 持有者、也是唯一的 `mHoldScreenWindow`；本机 `mScreenOffTimeoutSetting=15000`（15 秒），也就是说只要锁屏在屏幕上，框架的熄屏超时永远不会生效，电视不会自己进入待机。锁屏因此不再持有 `FLAG_KEEP_SCREEN_ON`，只保留 `TURN_SCREEN_ON`；`LockActivity.launch()` 在面板不亮时直接返回，唤醒后由 `ACTION_SCREEN_ON` 重新主张锁屏。
- 同一段待机的前后，前台窗口、输入设备列表与 `screen_brightness` 都没有变化，不能当判据；面板状态（`Display.getState()`，与 `dumpsys display` 的 `mState` 同源）是目前实测唯一会随待机改变的第二个信号。

据此，2.5.16 的计时与锁屏口径是：

- 计时基线是 `SystemClock.uptimeMillis()`，不是 `elapsedRealtime()`。后者在休眠期间照旧前进，而一次补跑的 tick 会把整段挂钟差当作观看时长扣进当天额度——Sony BRAVIA 4K 2015 上家长确认电视可以连续数十小时处于待机，并要求待机一律不计入。2.5.16 的实机采样给这条防线加了限定：本机的 `uptimeMillis` 在待机里照样前进（77 分钟待机走了 69 分钟，Sony 的 `heat_control` 与 `WebApiWakeLock` 让 SoC 不 suspend），所以时钟只能算「设备真 suspend 时的第二重保护」，把待机挡在外面的是面板状态。`countedDelta()` 同时封顶单个周期的补量（`MAX_COUNTED_TICK_MILLIS`，4 秒），主线程被卡住、看门狗补跑或服务重启都只会补一个周期。亮屏、灭屏、服务创建和解除锁定四个入口都重新对齐基线，因此熄屏的分钟不会在唤醒那一刻被追溯扣除。
- 额度判定是「面板亮着且未锁定」，2.5.16 起由 `PanelState.isLit()` 回答：`PowerManager.isInteractive()`（API 19 用 `isScreenOn()`）与 `Display.getState() == STATE_ON` 两个判据同时成立才算，任一不成立即视为待机，doze 与屏保也算待机。锁屏、`LockActivity.launch()` 与计时共用这一个判据，避免出现两套「屏幕亮不亮」的口径。
- 关屏、锁屏与待机都不计时；跨到更晚的日历日才由 `Prefs.rollOverIfNeeded()` 清零，时钟回拨不给免费的额度重置。
- 右上角角标由 `GuardService` 持有：未锁定时 `updateCountdown()` 显示「剩余 MM:SS」，最后 5 分钟转红。2.5.10 曾在这天被家长密码解锁时把同一枚角标换成琥珀色「今天不限时」（`showUnlimitedNotice()`）并与面板的 `today_override` 提示对齐；2.5.12 把这一状态、这段提示和那一行标记一起删除——家长密码不再买时间，角标就只剩下倒计时一种形态，也不会再出现空白角标被孩子读成「防护已关」的情形。锁定态不显示角标，只有全屏黑幕与锁屏 Activity。
- 悬浮窗权限缺失时不贴角标（API 23 起 `Settings.canDrawOverlays`），面板另有「倒计时未开启：需允许悬浮窗权限」警告；API 19/20 由清单权限决定，不存在运行时撤销。
- `CountdownOverlayTest` 在 API 19/24/33 断言：模拟一小时深度休眠后 tick 不增加当天时长；tick 被饿 20 分钟后最多补 4 秒；熄屏十分钟不扣、唤醒后只从亮屏那刻开始计；未锁定时窗口里恰有一枚文本角标、文字以「剩余 」开头且额度接近 30 分钟减去已看时间，反复 tick 不叠加；面板给出 10 分钟临时加时后同一枚角标的剩余正好多出 600 秒；无悬浮窗权限时不贴任何窗口；额度耗尽时进入锁定且没有倒计时角标。2.5.16 另在 API 24/33 断言：电源管理仍报 `Awake` 而面板报 `STATE_OFF` 的十分钟一分钟都不算、回到 `STATE_ON` 后只补唤醒之后的两秒；面板报 `STATE_DOZE` 的十分钟同样不算（若第二判据失效，tick 会补满 4 秒封顶量，这两条断言必然失败）。`OnScreenLockTest` 断言锁屏窗口不再持有 `FLAG_KEEP_SCREEN_ON`、仍持有 `FLAG_TURN_SCREEN_ON`，且面板熄灭时 `LockActivity.launch()` 不启动锁屏、面板点亮后仍会启动。`PrefsAuthTest` 另断言旧版写下的 `unlocked_today` 在升级后的第一次构造 `Prefs` 时被删除，且删除后时长锁重新生效。

## 设置入口保护与恢复

2.5.9（versionCode 40）以普通应用恢复原有密码拦截为目标，不要求系统预装、root 或 Device Owner：每次进入设置页都要求家长密码，同时消除「输入密码后再次要求输入密码」的验证死循环。`MainActivity.requireParent()` 保护图标入口，`GuardService` / `LockActivity` 保持额度锁定，`AppLockService` 保护已识别的设置及卸载页面；三条路径分别验收，不能把图标有密码等同于系统设置受保护。

- 无障碍声明 `canRetrieveWindowContent=true`，仅调用 `getRootInActiveWindow()` 获取所属包名并回收节点，不遍历控件、不读取或保存文字。查询可能返回空，窗口事件仍保留为识别来源；查询异常记录日志并在面板提示，定时回查继续重试。
- 连接时清除旧前台和设置解析缓存，250 ms 回查重新查询当前窗口，不依赖重连后必定补发窗口事件。未知包变化时立即重新解析，查询失败约 1 秒重试，同一未知包正常约 30 秒重新识别；局部失败不丢弃已识别的受保护包。
- `isEnabled()` 检查无障碍总开关及启用组件，兼容完整和缩写组件名；`isConnected()` 来自服务连接、解绑和销毁回调。配置已启用不代表服务正在运行。普通应用不能自动重新开启系统已关闭的无障碍权限。
- 每次进入设置页都要求家长密码：`AdminSession` 有效不作为设置页通行证，验证页与时长锁屏照常拉起。Sony BRAVIA 4K 2015 上的死循环不是靠记住密码修的，而是靠下一条规则修的：管理面板是半透明窗口，它下面的设置页仍然可见并持续上报自己是前台窗口，拦截服务因此在面板之上反复拉起验证页；面板 `onPause` 会撤销会话，下一个验证页就真的再次要求输入密码，输入后循环重现。日志证据是 `MainActivity` 启动后约 0.15～0.4 秒紧跟一条 `AdminAuthActivity` 启动，循环到家长放弃为止。
- 拦截服务在自家家长界面在屏时一律不动手，这是现行唯一的防死循环机制：验证页可见、已授权面板可见或 `GuardService` 的家长界面租约有效都不再拉起验证页或锁屏，不依赖具体机型的前台窗口判定。家长会话本身不放开设置，每次进入仍要家长密码。
- 2.5.15（versionCode 46）在这条规则之上加了一个例外，也只有这一个例外：家长从管理面板按返回键或 `00 关闭面板` 退出时，`MainActivity.closePanel(true)` 向 `GuardService.grantDesktopPass()` 要一张 `DesktopPass` 通行证，交出屏幕前不再补弹锁屏，黑幕一起撤。`AppLockService.enforceForeground()` 只在该窗口是 `HOME` intent 解析出来的桌面时放行（解析结果按 30 秒缓存，认不出桌面就不豁免），桌面的第一个窗口把它花掉，锁屏立刻回来；`GuardService.keepLockInFront()` 只在 `AppLockService.isConnected()` 为真时尊重通行证，拦截服务一断就当场作废并把锁屏拉回来，`grantDesktopPass()` 同样在没有拦截器时直接拒绝。灭屏广播与 `exitLock()` 都会结束通行证，重新亮屏先看到锁屏；`LockActivity.launch()` 本身不加通行证判断，所以验证页返回、`33 立即锁定`（`closePanel(false)`）和孩子在锁屏按 HOME 全都照常锁定。通行证不写时长、不改 `locked`、不清额度。
- 只有显式维护授权短时放行系统页；管理员激活返回（含取消）、更新返回或维护到期后恢复拦截；未经验证按返回不露出原设置页。
- `AppLockServiceTest` 覆盖当前窗口恢复、重连、解析重试、连接状态与维护边界，并断言「有效会话之上的设置页仍要密码」「维护结束后同一个设置页重新要求密码」；`SettingsGateLoopTest` 用真实的验证页→面板交接和「面板之下的设置页仍上报前台」复现死循环，断言面板在屏时不弹验证页也不弹锁屏、家长离开后同一个设置页重新要密码、时长用尽的锁屏在家长离开面板后回来；`MainActivityRemoteTest`、`MainActivitySettingsTest` 验证图标鉴权和真实警告。自动化不替代电视上的桌面长按、应用详情和卸载入口验收，不能据此认定本次电视故障根因。

## 防卸载附加保护

普通设备管理员仍启用时，系统的直接卸载检查会拒绝移除；这不等于所有设置流程都无法卸载，也不等于要求本应用密码。设置入口拦截才是日常保护主线。

- 家长在面板按 `55`，经系统 `ACTION_ADD_DEVICE_ADMIN` 确认页激活；应用不静默激活。仅在限时维护授权下打开该页，返回后结束维护并按 `isAdminActive` 读回真实结果。
- 系统 `DeviceAdminAdd` 的部分流程可通过 `uninstallPackageWithActiveAdmins()` 停用并卸载。`onDisabled` 发生在停用后，只能撤销旧授权并尝试拉起密码门，不能否决已经完成的操作。
- 关闭防护仍走 `DeviceProtection.remove()` 的家长确认和读回核验，不恢复出厂。普通模式不承诺阻止系统强停、清除数据或未识别的厂商入口。
- `UninstallProtectionTest` 与 `DeviceProtectionTest` 覆盖 API 19/24/33 的激活维护、返回恢复、停用后重新验证、策略读回与系统确认页无法解析的情况；不是实际卸载验收。

## 正式发布

私钥保存在仓库外；默认读取 `~/.config/tv-kids-guard/signing.properties`，也可用 `TVGUARD_SIGNING_PROPERTIES` 指定：

```properties
storeFile=/绝对路径/release.keystore
storePassword=<密钥库密码>
keyAlias=<原签名别名>
keyPassword=<私钥密码>
```

递增版本号，使用原签名构建。输出目录需为空或不存在：

```bash
./gradlew testDebugUnitTest assembleRelease
python3 -I -B tools/release_update.py --apk app/build/outputs/apk/release/app-release.apk --out app/build/outputs/ota --notes '更新说明'
python3 -I -B tools/release_update.py --apk app/build/outputs/apk/release/app-release.apk --out app/build/outputs/ota --notes '更新说明' --publish
```

发布前检查 `tv-kids-guard.apk`、`update.json` 和 `SHA256SUMS`。发布工具只上传这三个文件，并校验 `config/release-certificate.sha256` 中的公开证书指纹；不要提交私钥或签名密码。
